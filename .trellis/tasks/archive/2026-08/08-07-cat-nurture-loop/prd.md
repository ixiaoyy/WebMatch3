# 猫咪轻养成与小鱼合成循环

## Goal

把当前“找鱼＋三条同类消除＋猫咪辅助”改造成以猫咪为主角的无压力轻养成体验：玩家在隐藏鱼群中找齐三条同种小鱼，它们合成一条明显更大的完整鱼并自动喂猫；猫咪以持续成长、可见动作和环境变化回应玩家，同时保留五秒即可开始、随时可以离开的安静桌面定位。

## Background

- 当前核心玩法是在隐藏鱼群中寻找可选小鱼，放入七格托盘，三条同类自动消除；清除结果主要推动植物成长。
- 当前猫咪可以被抚摸、协助寻找隐藏小鱼，并接受直接拖拽或键盘 `F` 投喂；累计三条后进入吃饱、趴卧和睡眠状态。
- 当前五张猫咪姿态资源均为单帧静态 WebP。互动主要通过整张图片的微小位移、旋转和淡入淡出模拟，不能表达尾巴、眼睛、爪子、进食或移动等具体动作。
- 现有喂食反馈与猫咪文字反应会同时设置同一图片元素的 `animation` / `transform`，后声明的动画会覆盖前者；姿态切换使用顺序淡出再淡入，部分时间猫咪完全不可见。
- 产品既有约束强调无计时压力、无离线惩罚、无强制日常任务，并要求键盘、触摸、窄屏和 reduced-motion 等价体验。

## Confirmed Product Direction

- 猫咪成为长期体验的核心主角；找鱼凑三保留，但定位为获取食物、互动机会和环境成长的主动玩法。
- 原有“三条相同完整鱼自动消除”改成“三条同种小尺寸鱼合成一条大尺寸鱼”；避免切割角色造成不适，难度继续来自鱼种辨认、遮挡和托盘规划，不引入计时或步数限制。
- MVP 采用无压力轻养成，不引入饥饿衰减、生病死亡、连续签到、每日任务、商店、抽卡或多货币体系。
- 大鱼合成后立即自动送给猫并触发回应，不为 MVP 增加零食库存和二次投喂步骤；单条小鱼不能直接喂猫。
- 猫咪可以持续接受完整鱼，不设置永久吃饱上限；每累计三条触发一次短暂的吃饱、趴下、睡眠与醒来表现，结束后自动恢复可喂状态。
- MVP 先实现三个亲密阶段：初见（0–2 条）、熟悉（3–8 条）、亲密（9 条及以上）；以动作和猫咪身边的毛毡物件变化表达阶段进展，不依赖常驻数值 HUD。
- 植物保留为次级环境成长线，不能与猫咪反馈争夺主要注意力。

## Requirements

### R1 — 三条小鱼合成大鱼并直接服务猫咪养成

- 场上和托盘中的可收集对象均为轮廓完整的小尺寸鱼，不显示切口或身体分段。
- 只有同一鱼种的三条小鱼能够合成；混合鱼种不得误触发。
- 合成后必须在同一反馈序列中表现三条小鱼聚拢、变成明显更大的完整鱼、送达猫咪并触发可辨认的进食或开心动作。
- 玩家应在不阅读状态文案的情况下理解“三条同种小鱼会合成大鱼并喂给猫咪”。
- 奖励反馈不得增加确认弹窗、库存整理或领取按钮。
- 小鱼仍需遵守可选择、遮挡、隐藏搜索与托盘容量规则；生成结果必须保证每种鱼数量可被三整除并存在完整解法。

### R2 — 三阶段持久亲密成长

- 新增可持久化的猫咪亲密进度和三个阶段；阶段只能前进，不因离开页面或长时间未访问而后退。
- 每条自动喂食的完整鱼都持续累积亲密进度，不因猫咪曾经进入吃饱或睡眠表现而停止。
- 每个阶段至少带来一项可见变化，例如新动作、玩具、猫窝或猫咪主动行为。
- 单次凑三提供即时回应，阶段变化提供更强但仍安静的里程碑反馈。

### R3 — 真实、语义明确的猫咪动作

- MVP 至少覆盖待机、进食、被抚摸和移动找鱼四类动作；睡觉/醒来继续保持可辨认状态。
- 待机需要低频呼吸、眨眼或摆尾，不能长时间完全静止。
- 不再通过旋转整张角色图片冒充看、摆尾、呼噜、抬爪或打哈欠。
- 动画状态必须有明确优先级，喂食、互动、找鱼和待机不得互相覆盖或使猫咪短暂消失。

### R4 — 无压力、可中断

- 不设置饥饿倒计时、离线状态推进、连续登录奖励、失败惩罚或必须定时处理的需求值。
- 任意动画和阶段反馈不得阻止玩家离开页面；返回后保留已完成的永久进度。
- 一次完整“找到同种头、中、尾三段并看到完整鱼自动喂猫”的路径应适合约 30–90 秒的短会话。

### R5 — 保留现有输入与可访问性契约

- 鼠标、触摸、键盘方向键、Enter/Space、`F`、猫咪菜单与焦点恢复继续可用；`F` 改为将当前小鱼放入托盘的等价快捷键，不再绕过合成规则直接喂猫。
- `prefers-reduced-motion` 下使用清晰的静态姿态、亮度或文案变化表达相同状态，不依赖运动理解结果。
- `320px` 宽度、紧凑小窗和桌面视口不得出现关键内容重叠或横向滚动。

## Acceptance Criteria

- [ ] AC1. 新玩家第一次集齐三条同种小鱼时，仅凭画面即可理解它们合成大鱼并自动送给猫咪。
- [ ] AC2. 三条同种小鱼能稳定合成；混合鱼种和不足三条不会误触发。
- [ ] AC3. 三条以内的完整拼鱼奖励会产生第一个永久且可见的猫咪成长变化。
- [ ] AC4. 猫咪可持续接受任意数量的完整鱼；每累计三条只触发短暂休息表现，结束后自动恢复，不拒绝后续自动喂食。
- [ ] AC5. 猫咪亲密阶段可跨页面重新加载保留，且离线期间不会降低或自动推进。
- [ ] AC6. 待机、进食、被抚摸和移动找鱼具有不同的动作语义，不再共享整图摇晃替代动作。
- [ ] AC7. 同一时刻只有一个主猫咪动作拥有表现控制权；喂食反馈不会被文字反应动画覆盖，姿态切换不存在完全透明空档。
- [ ] AC8. 现有找鱼、猫咪协助和植物成长继续可用；托盘规则升级为三段拼鱼，不增加经典棋盘、关卡选择或常驻数值 HUD。
- [ ] AC9. 每个生成鱼群都能通过合法的同种三条组合全部解完；鱼种分布不会引入无解局面。
- [ ] AC10. 键盘、触摸、`320px` 紧凑视口和 reduced-motion 均能完成核心养成循环并获得等价反馈。

## Constraints

- 养成状态默认只做本地持久化，不新增账号、后端、数据库或数据库迁移。
- 保留现有毛毡猫视觉身份、冷色桌面环境和低刺激反馈风格。
- 生产代码新增方法需添加方法级注释，说明用途、关键参数和返回结果。
- 不覆盖或暂存用户现有 `.trellis/qa/` 与 `design-qa.md` 未跟踪内容。

## Out of Scope

- 传统交换式棋盘消消乐、步数限制、失败重开和数字关卡地图。
- 将单条小鱼直接喂猫，或在大鱼合成后要求玩家手动领取、存放或再次投喂。
- 饥饿、清洁、健康、死亡、离线衰减和强制照料。
- 商店、付费货币、抽卡、装扮库存、每日任务和连续签到。
- 第一版实现五个以上成长阶段或大量季节内容。

## Open Questions

- 无。已确认猫咪可以持续接受自动喂食，吃饱与睡眠只作为每累计三条后的短暂表现状态。
