# 鱼群寻物与分波通关

## Goal

把游戏从“重叠鱼堆里点鱼、塞满七槽”收敛成清楚的鱼群寻物：所有鱼完整可见、沿自然流线分布，玩家寻找当前能凑成三条的同种鱼。每完成一组，三条鱼仍聚拢并喂给小猫；达到本关目标组数后才进入下一关。

视觉基准采用本次讨论最后确认的 1+3 融合稿：冷紫色雨天窗台、右侧猫与花盆、底部轻量托盘、左侧大留白中的 S 形鱼群。禁止随机堆叠、遮挡层和任意角度旋转。

## Requirements

### R1 — 第一关是无压力教学关

- 第一关固定 3 个鱼种，每种恰好 3 条，共 9 条鱼。
- 三组鱼同时完整展示；玩家必须将三组全部凑齐，累计完成 3 组后才通关。
- 消除前两组时保留其余鱼，不刷新整页；完成第三组后进入第二关。

### R2 — 第二关起按波次寻找唯一三条

- 第二关起，每一波展示多个鱼种，但恰好只有一个鱼种出现 3 条，其余鱼种各出现 2 条。
- 玩家凑齐当前唯一三条后，整片鱼群刷新为下一波；未选中的鱼和托盘中的非匹配鱼一并清理。
- 同一关重复波次，直到累计完成目标组数才进入下一关。
- 每关目标组数按 `3、5、8、13、21、34…` 的斐波那契式序列增长。
- 可见鱼种数量随关卡逐步增加，最多使用现有 8 种鱼。

### R3 — 不再堆叠

- 所有鱼默认完整可见且可直接点击，不再依赖探照灯显影。
- 鱼沿 3 段自然鱼群流线排列，同种鱼分散在不同位置，不能并排提示答案。
- 鱼之间不得发生玩法遮挡；canonical layer 固定为单层，旋转限制在 `-8°～8°`。
- 桌面保持明显留白，鱼不得覆盖猫、植物、托盘和控制按钮。

### R4 — 选择、刷新与反馈

- 继续使用有效命中、按下反馈、鱼飞入托盘、三鱼聚拢、大鱼喂猫和植物成长。
- 普通点击只移除被选中的鱼；只有凑齐三条时才刷新后续波次。
- 刷新不得早于第三条鱼落盘、聚拢和喂猫反馈；旧鱼群先保留，反馈完成后再换成新鱼群。
- 第一关前两次组合不刷新；第二关起每次组合刷新。
- 七槽装满时只重开当前波次并保留本关已完成组数，不退回第一关。

### R5 — 输入与持久化

- 鼠标、触摸和键盘均可直接选择所有鱼，保留至少 `44px` 有效命中区和清楚焦点态。
- `prefers-reduced-motion` 保留按中、落盘、聚拢、喂猫、换波的先后关系。
- 页面重新打开仍按既有产品约定从第一关开始；植物成长、喂鱼总数和声音偏好继续持久化。
- 不新增数据库、迁移、网络服务或图片素材。

## Acceptance Criteria

- [x] AC1. 第一关恰好 9 条鱼、3 个鱼种、每种 3 条；前两次组合不换场，第三次组合后进入第二关。
- [x] AC2. 第二关起每一波恰好一个三条鱼种，其余可见鱼种各两条；组合后换波且同关进度加一。
- [x] AC3. 关卡目标依次为 3、5、8、13、21、34，未达到目标不升级，达到后进入下一关。
- [x] AC4. 所有鱼默认可见、单层、无遮挡，旋转不超过 8°，同种鱼不会集中排成明显答案。
- [x] AC5. 换波发生在捕捉、合成和喂猫因果链之后；旧鱼不会提前整页消失。
- [x] AC6. 七槽失败只重置当前波次，保留当前关卡及已完成组数。
- [x] AC7. 鼠标、触摸、键盘、reduced motion 和目标响应式视口均可完成主循环。
- [x] AC8. 纯引擎、控制器、存储兼容、lint、type-check、build 与浏览器交互验证通过。

## Constraints

- 保持安静、触感、发光材质和可随时离开的桌面体验。
- 不加入计时、分数、数字关卡 HUD、任务、货币、弹窗或糖果式庆祝。
- 复用现有鱼、猫、植物、托盘和壁纸素材。
- 新增方法必须有方法级注释；生产代码确认后立即暂存。
- 保留现有未跟踪 `.trellis/qa/` 与 `design-qa.md`，不得修改或纳入本任务。

## Out of Scope

- 真实捕鱼、鱼竿、渔网或物理追逐操作。
- 羊了个羊式遮挡层、方块牌面和层级解锁。
- 新增后端、账号、云存档或数据库结构。
