# 活鱼捕捉交互改造

## Goal

把当前“照到静态鱼后立即点掉”的交互改造成可感知、可预期且有连续空间因果的捕捉体验：玩家能够准确锁定眼前的小鱼，看见它被捞起并落入托盘；第三条同种鱼落盘后，三条鱼清晰聚拢成大鱼，再由小猫接住并触发植物成长。

本轮继续服务五秒钟、无压力、随时可离开的安静桌面体验，不改变纯三消规则、七槽失败、鱼群生成、长期成长或本地存储结构。用户已于 2026-08-10 明确接受“光圈引鱼、磁吸锁定、连续捕捉、三鱼合成与猫接鱼”的方向，并批准创建任务与实施。

## Background

已由当前源码和既有试玩证据确认：

- `FishPiece.vue:187-191` 的可见鱼尺寸在桌面为 `52–70px`、窄屏为 `62–78px`，实际按钮仍只有 `44×44px`；玩家可能点到可见鱼鳍或身体边缘却落在按钮外。
- `FishPiece.vue:74-87` 在 pointer up 立即发出 `activate`，`ambient-controller.ts:575-643` 随即提交引擎状态并从鱼场移除该鱼。
- `FishField.vue:649-654` 的源位置退场只有 `220ms` 缩小，没有连接鱼场与托盘的共享元素运动；普通选择反馈常量同样只有 `220ms`。
- 三鱼合成目前在同一次引擎状态变更中完成，托盘预览、合成鱼投递与小猫进食同时起步，总反馈约 `700ms`，导致第三条鱼落盘、三鱼聚拢和猫接鱼的先后关系不可辨认。
- `FishPiece.vue` 只有显影、引导、入场和邻鱼避让等条件动画，没有可见鱼的常驻生命运动；静止是当前实现契约，不是偶发渲染故障。
- `PRODUCT.md` 要求 canonical 鱼群排列稳定、纯规则可测试、至少 `44px` 目标、支持指针/触摸/键盘并保持克制动效。本轮允许 UI 投影层产生小范围活鱼运动，但 canonical 坐标与阻挡规则继续稳定。

## Requirements

### R1 — 所见即所得的磁吸命中

- 鼠标或精确指针点在已显影鱼的可见身体范围内时必须能命中，不再受 `44px` 透明按钮边界限制。
- 鱼场根据当前 UI 投影和真实 DOM 中心选择磁吸范围内最近的已显影、合法鱼；有效捕捉直径目标约 `72–80px`，重叠候选以最近中心稳定决胜。
- hover 或精确指针接近时提前高亮本次会捕捉的唯一鱼；pointer down 与 pointer up 绑定同一 ID，一次手势最多选择一条鱼。
- 点击无鱼区域产生克制水波或空搜反馈，不改变 canonical 状态；既有触摸扫描、键盘 Enter/Space、方向键和鱼按钮语义继续有效。

### R2 — 小鱼具有安静的生命感

- 当前显影或边缘预告鱼进行确定性、小幅、低频的摆尾/漂游，不修改 canonical `pile` 坐标、阻挡关系或存储快照。
- 鱼进入磁吸范围、获得焦点、被引导、被拖动或按下时停止漂移并形成稳定目标。
- pointer down 提供 `100–150ms` 的压缩、提亮或水波确认；玩家在状态提交前即可感知“按中了”。
- 非必要循环在页面 away、不可见状态或 `prefers-reduced-motion` 下停止。

### R3 — 单条鱼从源位置连续落入托盘

- 每次成功选择都从点击前鱼的可见中心生成捕捉替身，沿一条清楚但克制的弧线飞向选择前计算出的目标槽位，常规时长约 `480–560ms`。
- canonical 状态可以立即提交，但托盘中的真实鱼在捕捉替身落盘前不得提前可见；落盘后槽位短促下沉、回弹并显示鱼。
- 连续快速选择允许多个独立捕捉替身并存，不串槽、不丢 ID，也不重复触发引擎选择。
- 动画只使用当前鱼素材、CSS transform/opacity 和小范围滤镜，不新增运行时依赖或大面积持续昂贵效果。

### R4 — 第三条鱼形成可读的完整因果链

- 第三条同种鱼也必须先完成鱼场到托盘的捕捉运动；此前已在飞行中的同组鱼全部落盘前，不开始三鱼聚拢。
- 三条匹配鱼从各自真实槽位同步发亮并聚拢，再形成一条明显更大的同种鱼；大鱼至少保留一个可辨认的短暂停顿后再飞向小猫。
- 小猫的进食姿态、物理反馈、气泡文案、合成音效和植物成长不得在大鱼到达前抢跑；物理反应是主反馈，文案只是点缀。
- 从第三次按中到喂食主反馈完成目标为约 `1.4–1.8s`，期间不出现弹窗、分数、计时或确认按钮。
- 清空鱼群的 level arrival、满七槽 loss 和小猫 bond progression 继续遵守现有规则，只调整视觉时序以保持因果。

### R5 — 响应式、输入与可访问性

- `1280×720`、`430×560`、`320×568` 与 `320×240` 不出现关键元素重叠或横向滚动；捕捉路径以 surface-local 几何计算，适配普通页面与 Document PiP。
- 键盘鱼按钮、方向键光圈、Enter/Space、`F` 和触摸扫描仍能完成选择；磁吸 hover 不成为触摸或键盘的必要条件。
- `prefers-reduced-motion` 下取消漂游和长距离飞行，但必须按“按中确认 → 落盘 → 合成 → 喂猫”保留分阶段静态/淡变反馈，不能退化为瞬间消失。
- 新视觉替身全部 `aria-hidden` 且不抢焦点，现有 live region 继续播报真实游戏状态。

### R6 — 规则、持久化与素材边界

- 不修改 `selectPiece` 的匹配、七槽失败、换群、clear count 或随机生成语义。
- 不新增或修改数据库、迁移、网络服务、本地存储版本或持久化字段。
- 首版复用现有八种鱼、猫的 eating/full 等姿态和当前场景素材，不生成新图片。
- UI 动效状态为瞬时状态，刷新、PiP 移动或离开页面时可安全清理，不进入 snapshot。

## Acceptance Criteria

- [x] AC1. 桌面重叠鱼夹具中，点击可见身体边缘也能选中 hover 预告的同一条鱼；按下/抬起期间投影变化不会串选，一次手势只产生一次选择。
- [x] AC2. 已显影鱼具有可见但克制的漂游/摆尾，进入磁吸、focus、guided、dragging 或 pressed 状态后稳定；away 与 reduced-motion 下无非必要循环。
- [x] AC3. 普通选择能看见鱼从源位置连续飞入正确空槽；目的槽在到达前不提前显示真实鱼，落盘后有明确接触反馈，连续两次快速选择仍各自对应正确槽位。
- [x] AC4. 第三条同种鱼先落盘，三条鱼再同步聚拢成大鱼，大鱼随后抵达小猫；猫的 eating/full 物理反馈、声音和植物成长均不早于抵达阶段。
- [x] AC5. 三鱼主反馈约 `1.4–1.8s`，普通捕捉约 `480–560ms`；频繁重复操作无残留替身、截断动画或永久输入锁。
- [x] AC6. 鼠标、触摸扫描、键盘 Enter/Space、方向键与 `F` 路径继续工作；空点不改变状态，视觉替身不进入可访问树。
- [x] AC7. reduced-motion 保留四段可理解反馈；四个目标视口与可用的 PiP 路径没有横向滚动、关键遮挡或控制台 warning/error。
- [x] AC8. 引擎和 snapshot 结构无变化；相关纯函数/controller 测试、lint、type-check、build 与最终 `pnpm ci:web` 通过。
- [ ] AC9. 使用真实页面完成首次找到鱼、边缘点击、普通落盘、首次三鱼合成、小猫接鱼、满盘失败与清空换群的人工试玩。

## Constraints

- 保持 `PRODUCT.md` 的安静、触感、发光材质与五秒钟体验，不引入糖果式爆炸、持续音频或全屏庆祝。
- 动效优先使用 transform 和 opacity；滤镜限制在单条鱼、光圈和合成区域，任何循环只作用于当前显影/预告的少量鱼。
- 新增方法添加方法级注释，说明用途、关键参数和返回结果。
- 生产代码确认属于本需求后立即 `git add`；任务文档、测试和 QA 产物不自动暂存。
- 保留现有未跟踪 `.trellis/qa/` 与 `design-qa.md`，不得修改或纳入本任务。

## Out of Scope

- 重做壁纸、鱼、猫、植物或托盘的整体视觉世界。
- 修改匹配数量、七槽容量、失败重开、鱼群规模、品种数或长期植物成长曲线。
- 新增分数、关卡 HUD、计时、任务、货币、教程步骤页或强制等待。
- 引入 Canvas/WebGL、物理引擎、第三方动画库、新音频资产或新图片素材。
